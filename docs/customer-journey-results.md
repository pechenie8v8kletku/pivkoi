# Как меняется лента после действий закупщика

В каталоге 19 вымышленных компаний. Пекарня сначала ищет муку, потом переключается на упаковку. Салон выбирает средства для волос. Среди альтернатив есть печи для пекарен, курьерские пакеты и шампунь для собак.

Qwen строит профили при индексации, Qwen3-Embedding подбирает кандидатов. BGE отработал в 19 из 19 запросов ленты и поиска. Сервис принял 25 из 25 событий.

В каждом поиске закупщик последовательно открывает двух подходящих поставщиков, смотрит каждую карточку 12 секунд, первую отмечает лайком, по второй открывает контакт. Длительность просмотра передаётся синтетическим событием. Затем он возвращается в обычную ленту поставщиков без поискового запроса.

## Что увидел закупщик

**В трёх сценариях положительные действия изменили оценки компаний, но сохранили прежний порядок всей ленты.** При обнулении персонального веса после тех же событий порядок также совпал. Скрытие сработало сразу. Ниже — наблюдения прогона 26 ноября 2026 года.

* Пекарня открыла контакт «Зёрен Волги». Оценка поставщика муки выросла с 0,699 до 0,765, он остался шестым. У «Полевой мельницы», которую пекарня не открывала, оценка тоже выросла с 1,120 до 1,160. Её второе место сохранилось. До конкурента на первом месте с оценкой 1,251 она не дотянулась.
* Когда пекарня переключилась на пакеты, поиск сразу вернул четыре компании из четырёх размеченных. В обычной ленте упаковка уже занимала первое и третье места. После лайка и контакта она сохранила эти позиции, а второй осталась мельница.
* Для салона первые четыре места уже занимали подходящие поставщики. Пятым сервис показал «Лапу» с шампунем для собак. После действий по салонной косметике «Лапа» осталась пятой. После скрытия лидера она поднялась на четвёртое место. Это конкретное ложное совпадение, которое стоит включать в проверку качества.

Оценки выше — внутренние баллы ранжирования. На этих данных перенос сигнала на похожего поставщика виден в баллах, а улучшение позиций для покупателя не обнаружено.

## Условия опыта

Один каталог, два клиента, по четыре заранее размеченных поставщика на каждый запрос. Действия заданы сценарием. Глобальный граф, случайное исследование и бонус UCB отключены, seed равен 42. Опыт измеряет порядок компаний внутри этой синтетической выдачи. Для оценки конверсии в контакты нужны действия настоящих пользователей.

## Воспроизведение

Из каталога `customer_recommendation` запустить `.venv/bin/python scripts/customer_journey.py`. Скрипт создаёт копию индекса для нового покупательского сеанса и сохраняет в `local_experiments/` готовый отчёт и журнал запросов, выдач и событий.
