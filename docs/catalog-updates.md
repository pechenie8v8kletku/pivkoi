# Обновления каталога и вызовы моделей

Модели обслуживают запросы в постоянно работающем процессе. Обновление
товаров не перезапускает Qwen и не обучает его веса. Генератор профиля
и Qwen-эмбеддер выполняют разные задачи; локальный chat пока scripted.

`PUT /v1/clients/{id}` принимает полный snapshot, не частичный список SKU.
Отсутствующие товары удаляются. Максимум сейчас 5000 товаров на компанию.

## Реализовано

- Идентичный snapshot не вызывает моделей.
- Цена, остаток, единица измерения, регион не вызывают генерацию профиля.
- Для профиля выбирается до `PROFILE_PRODUCT_LIMIT` товаров (по умолчанию 40):
  детерминированный обход категорий по кругу, без отраслевых таблиц.
- Неактивные товары исключены из выборки. Точные дубли названия, категории
  и сокращённого описания не занимают повторные места.
- Описание представителя ограничено 500 символами. Операционные поля
  нормализованы, чтобы кэш соответствовал фактическому входу генератора.
- Ключ профиля зависит от выбранного входа, версии алгоритма и модели.
  Изменение SKU вне выборки больше не требует повторной генерации.
- Все активные товары с остатком не равным нулю остаются отдельными
  поисковыми документами, включая товары вне выборки. Полные тексты
  эмбеддингов кэшируются по тексту, модели и endpoint: неизменные
  документы не требуют повторного inference.
- Изменённый товар вне выборки обновляет поисковый документ и время
  изменения контента, даже если общий профиль переиспользован.
- Запись нового snapshot и контекста происходит после успешной индексации.

Нулевой остаток не меняет постоянную специализацию профиля, но исключает
SKU из поисковых документов. Компания всё ещё может находиться по профилю;
это не подтверждение текущего наличия конкретного товара.

## Ограничения и дальнейшая работа

Выборка по категориям — не семантическая кластеризация и не топ продаж.
Если категории пустые/грубые, разнообразие внутри них не гарантировано.
Если категорий больше лимита, часть не войдёт. Обновление вне выборки
может изменить товарный поиск без изменения общего описания бизнеса.
Пока нет отдельной сводки всех категорий или периодической полной сверки.

Для следующего масштаба: устойчивые представители кластеров по уже
кэшированным эмбеддингам, краткая сводка категорий, общий токен-бюджет,
объединение частых изменений в очередь и versioned background indexing.
Это ещё не реализовано. Текущий snapshot синхронный, под общей блокировкой
одного worker; сборка документов и SQL-проверки кэша по-прежнему проходят
по каталогу. Отсутствие повторного inference не означает O(1) обновление.

После обновления версии алгоритма следующий snapshot один раз обновит
профиль; это не перезапуск модели. Проверены 100 SKU, изменение вне
выборки, изменение представителя, деактивация, дубли и перестановка SKU.
